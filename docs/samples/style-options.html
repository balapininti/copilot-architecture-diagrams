Which diagram style should the skill draw?

Same made-up system in four styles: an online shop spread across 4 linked repos (shop-web, order-api, payment-service, shared-contracts). Click any you like. You can pick more than one.

A

Pictorial icons, grouped by repo

Pictures for each kind of thing (person, web app, server, database, queue, cloud), a colored box per repo, numbered steps along the arrows. The look you'd get in draw.io or Visio with an icon set. Output: .drawio file you can edit, plus PNG/SVG.

B

Standard architecture boxes (C4 style)

The industry-standard "C4" look: solid boxes saying what each part is and what technology it uses, and a plain sentence on every arrow. Less pictorial, very consistent. Output: Mermaid or PlantUML text that shows up as a picture in GitHub / Azure DevOps wikis, plus PNG.

C

Repo link map (how the repos connect)

Each repo is a card showing its key files and classes. The lines show exactly how repos link: API calls, message topics, shared packages. Each line points to the code where the link was found. Best when the question is "what breaks if I change this repo?" Output: SVG/PNG, plus an HTML version you can click through.

D

Whiteboard sketch

Hand-drawn look, like someone sketched it in a meeting. Friendly for walkthroughs and slides; signals "overview, not blueprint". Output: Excalidraw file you can keep editing, plus PNG/SVG.
